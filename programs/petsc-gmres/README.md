# petsc-gmres

A PETSc KSP (GMRES + GAMG algebraic multigrid preconditioner) benchmark:
load the `stokes2` sparse matrix (4,260,568 rows, 256,285,536 nonzeros —
a Stokes flow saddle-point system on an ellipsoid mesh, generated via
Gmsh/FreeFEM by Atsushi Suzuki), solve `Ax = b` for a known `x`, report
the relative L2 error and GMRES-iterate wall-time (`FOM: ranks=<N>
ksp_iter_time_s=<t>`).

The FOM measures the GMRES **iterate only** — `KSPSetUp(ksp)` is called
explicitly before the timed `KSPSolve`, so GAMG setup (coarsening + PtAP)
is excluded. The iterate is the MatMult-bound SpMV loop that tracks memory
bandwidth / Flop/s; setup is communication-bound and is read off
`-log_view` (`PCSetUp_GAMG`, `MatMult`, ...) instead.

Source (`src/GMRES-PETSc.cpp`) is vendored directly in this directory
rather than fetched at build time. PETSc itself is fetched via
`bk_fetch_source` from its official repo, pinned to `v3.25.2`.

Confirmed working on Rikyu (GB200 NVL4), Fugaku (A64FX), and R-CCS
Cloud's DGX Spark (`RC_DGXSP`, GB10 Blackwell) — see this app's `build.sh`
for the per-system recipe.

## Fixed-iteration measurement and numerical diagnostics

Performance runs request `-ksp_max_it 500 -ksp_rtol 1e-14`, retaining the
configured GMRES restart size (default 100). This requests, rather than
unconditionally forces, 500 iterations. The application records the actual
iteration count, configured limit/tolerance and PETSc stop reason. Reaching
500 with `KSP_DIVERGED_ITS` is the expected iteration-limit termination for
this benchmark, not evidence of numerical convergence. A converged stop at
exactly 500 is also eligible. Early convergence, other abnormal stops and
non-finite diagnostics do not emit the fixed-500 FOM; their logs are retained.
They return a nonzero benchmark exit status. Early convergence is not itself
a numerical failure; it does not complete the requested performance workload.

After timing `KSPSolve`, the application explicitly computes the final true
residual `||b-Ax||_2` and its relative value `||b-Ax||_2 / ||b||_2`, before
modifying the solution for the existing relative L2 solution-error diagnostic.
If `||b||_2` is zero, the absolute residual is still reported and the relative
residual is `unavailable`. These quantities are distinct from a potentially
preconditioned or estimated residual used by PETSc's convergence test.
The extra calculations run in the `Final diagnostics` logging stage, excluded
by `FOM.awk` from the original event breakdown and outside the FOM timer.
`results/solve.log` records the diagnostics; `results/petsc.log` retains the
complete staged event log. Both are kept by existing CI artifact collection,
including failed runs. Result FOM version is `ksp_iter_time_500`; older
variable-iteration timings are not directly comparable to this measurement.

No formal numerical acceptance range has been established for this input.
Previous stokes2 relative solution-error observations around 0.23–0.26 are
measurement examples, not pass/fail limits. Parallel reduction order can
change convergence; neither a different error nor an equal iteration count
alone establishes a bug, numerical validity, or identical operation counts.
The audikw_1 residual examples concern a different matrix and are not stokes2
acceptance criteria. Final residuals are diagnostic observations without an
application-defined magnitude threshold. Reference convergence-history
comparisons can be considered separately when numerical criteria are defined.

## `-pc_gamg_square_graph 0`

Required on every system, at any rank count above 1 (single-rank runs
happen not to trigger it, but don't rely on that). Without it, GAMG's
default aggressive-coarsening graph-squaring step blows up on the matrix's
connectivity — a `CUSPARSE_STATUS_INSUFFICIENT_RESOURCES` crash on GPU,
or a genuine multi-GB single-allocation PETSc "Out of memory" abort on
CPU. Both `build.sh`'s configure line and `run.sh`'s launch command
already account for everything needed except this flag, which is passed
explicitly in `run.sh`.

## Staging the data

The matrix is generated by a FreeFEM script (`StokesPETSc0.edp`) that
solves a Stokes flow on an ellipsoid mesh and writes the resulting matrix
directly to PETSc binary format via `ObjectView(A, format="binary")` —
the same format as PETSc's own `MatView`, so no separate conversion step
(e.g. `mtx2petsc`) is needed. The `MatLoad` call in `GMRES-PETSc.cpp`
reads it directly.

Pre-staged at the per-site `CX_input` local-file directory (the shared
staging convention for this deployment: RIKYU `/data1/rkp00015/CX_input`,
R-CCS Cloud `/lvs0/rccs-nghpcadu/CX_input`, Fugaku
`/vol0500/share/ra250029/CX_input`), like this repo's `ffb` and
`LQCD_dw_solver`, which pre-stage their own — much larger — source
archives rather than fetching them at build/run time:

| system | path |
|---|---|
| RIKYU | `/data1/rkp00015/CX_input/petsc-gmres/stokes2.dat` |
| Fugaku | `/vol0500/share/ra250029/CX_input/petsc-gmres/stokes2.dat` — use the `/vol0500` mount alias, not `/vol0005`, in an actual path; `/vol0005` is the volume name but doesn't resolve from a compute-node job. Covered by this app's `FJ` queue.csv `GFSCACHE` declaration (`/vol0002:/vol0003:/vol0004:/vol0005`), so no per-app `-x` handling is needed |
| RC_DGXSP | `/lvs0/rccs-nghpcadu/CX_input/petsc-gmres/stokes2.dat` — `/lvs0` is mounted and readable on the ng-dgx compute nodes (verified with a compute-node read test) |

Every copy has SHA-256
`01971e1fb37268a195ff3d96c7800d3f7cf6a37c2ddfe397825c62b3b592bdaf` —
check a fresh copy against it before use.

`run.sh` records the actual matrix size and SHA-256 before starting MPI.
`input-manifest.json` describes the reference copy documented here; it is not an
execution gate. `BK_PETSC_GMRES_MATRIX` selects the input location, and a different
file is recorded with its own content identity rather than rejected by Benchkit.
Result `Exp` remains `stokes2` even when the matrix file is relocated or renamed.
Compare the recorded content digest as well as the case name. An unavailable
observation is marked as such and does not block MPI. A failed MPI process still
stops FOM emission; execution evidence is retained separately in CI artifacts.
Scientific acceptance remains application-owned. Input hashing adds a full file
read before the solver's measured interval.

To re-stage on a system: copy the `stokes2.dat` file (3,092,468,720 bytes)
from an existing location above. To regenerate from scratch, run the
FreeFEM script (`mpirun -np 8 FreeFem++-mpi StokesPETSc0.edp`) which writes
`A.dat` in PETSc binary format — rename to `stokes2.dat`. Verify: 4,260,568
× 4,260,568, nnz = 256,285,536.
